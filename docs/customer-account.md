# Кабинет пользователя

| Адрес | Назначение |
|---|---|
| `/account/` | Фото, телефон, имя, email, дата рождения, пол |
| `/account/signup/` | Регистрация покупателя |
| `/account/login/` | Вход по email и паролю |
| `/account/logout/` | Выход, только POST |
| `/account/password/` | Смена пароля |
| `/account/environment/` | Просмотр и добавление окружения |
| `/account/environment/<id>/edit/` | Изменение своей записи |
| `/account/environment/<id>/delete/` | Удаление своей записи, только POST |
| `/account/recipients/` | Список адресатов и дат поздравлений |
| `/account/recipients/add/` | Добавление адресата |
| `/account/recipients/<id>/edit/` | Изменение адресата и памятных дат |
| `/account/recipients/<id>/delete/` | Удаление адресата, только POST |
| `/account/avatar/` | Приватная фотография текущего пользователя |

На главной есть ссылка «Войти» / «Кабинет». Существующие пользователи могут войти со своими
email и паролем. Недостающий профиль создаётся при первом открытии кабинета.
Регистрация создаёт обычного покупателя, профиль и назначение роли `customer`.

`CustomerProfile` дополнен полями `avatar` и `gender`. Дата рождения и пол необязательны.
При смене email требуется текущий пароль. Права и служебные заметки не входят в публичные формы.
Пользователь и профиль сохраняются в одной транзакции.

Фото: JPEG, PNG, WebP, до 5 МБ и 16 мегапикселей. Сервер проверяет содержимое и MIME,
создаёт JPEG 512×512 без исходных метаданных. Старое фото удаляется после фиксации изменения.
Изображения доступны только владельцу через `/account/avatar/`. В production нельзя
подключать публичную раздачу каталога `media/avatars/`.

`CustomerConnection`, таблица `customer_connections`: владелец, свободный текст `label`,
даты создания и изменения. Количество записей не ограничено, вывод — по 20 на страницу.
Одинаковые названия разрешены. Можно вводить «супруга», «тёща», имя или заметку.
Изменить или удалить запись может только её владелец.

## Адресаты

`CustomerRecipient`, таблица `customer_recipients`: имя, телефон, произвольное описание связи
с пользователем и заметка. Количество адресатов не ограничено, список выводится по 20 на страницу.

`RecipientCelebrationDate`, таблица `recipient_celebration_dates`: название события, дата и признак
ежегодного повторения. У одного адресата может быть любое количество памятных дат. Новые строки
добавляются кнопкой «Добавить дату», существующие можно изменить или удалить вместе с адресатом.
Все операции проверяют владельца объекта; отправленные клиентом идентификаторы пользователя
игнорируются.

Миграция адресатов: `accounts/0005_customerrecipient_recipientcelebrationdate_and_more.py`.

Миграция: `accounts/0003_customerconnection_customerprofile_avatar_and_more.py`.

Проверка 12 сентября 2026: **74 теста прошли**, включая 24 теста кабинета на PostgreSQL.
Django check, линтер и проверка миграций — без ошибок.
В браузере проверены регистрация, профиль, окружение, повторный вход и ширины 320/390/768/1440.

Подтверждение email, восстановление пароля по почте, история заказов и серверное избранное
не входят в эту реализацию. Подарок/промокод из примера не добавлялся: такая акция пока
не настроена в GIOIA.
